# Poietra

友人と、AI と。編集できる構造を保ちながら、一緒に動画を作るブラウザ編集環境。

2026-09-15 のハッカソン向けに実装中です。画面の基準と決定事項は [AGENTS.md](AGENTS.md) を参照してください。

## 開発

Node.js 24 以上、pnpm 10、Rust（`wasm32-unknown-unknown` ターゲット）を使います。

```bash
pnpm install
pnpm build:wasm
pnpm dev
```

開発サーバーは `http://localhost:5173`。Composition の配置・表示期間、オブジェクト別の Transition、ベジェ移動パス、連結・整列、共同編集、数式と動画書き出しを実装しています。AI はサーバー側のキーを設定すると使えます。

AI はサーバーの `OPENAI_API_KEY` を使います。設定例は [.env.example](.env.example)。実際のキーは `.env` に設定し、Git には含めません。

```bash
pnpm typecheck
pnpm test
pnpm test:core
pnpm test:e2e
pnpm test:export
pnpm test:collaboration
```

## 共有環境（Cloudflare）

[Poietra を開く](https://poietra-hackathon.yumaboda-official.workers.dev)

Workers が画面と API を配信し、部屋ごとの Durable Object が WebSocket 同期と SQLite 保存を担当します。描画・Rust WASM の時間評価・WebCodecs 書き出しはブラウザで行います。

```bash
pnpm build:web
pnpm dev:worker
# 別ターミナル: 本番と同じ Workers 実行環境で共同編集を検証
POIETRA_TEST_URL=http://127.0.0.1:8787 pnpm test:e2e
```

配置先は Yumaboda の Cloudflare アカウントです。`wrangler.jsonc` の `account_id` に固定しています。別アカウントに配置するときはこの値を変更してください。

```bash
pnpm exec wrangler login
pnpm run deploy
# AI のキーをサーバー側の Secret に設定（対話入力）
pnpm exec wrangler secret put OPENAI_API_KEY
```

ローカルの Workers で AI を試す場合は `.dev.vars.example` を `.dev.vars` にコピーしてキーを設定します。キーをクライアントや Git に含めないでください。

Share でコピーした URL を別のブラウザで開くと、同じ部屋に参加します。リンクを知っている人が編集できます。編集データはサーバーと各ブラウザに保存され、再接続時に同期されます。再生位置・選択は各自で操作でき、取り消しは自分の変更が対象です。ローカル Node 開発版のファイル保存は 200 ms まとめて実行し、共有環境では SQLite の保存完了後に配信します。

左上の **P** から、新規プロジェクトの作成・例の複製・`.poietra.json` の保存と読み込みができます。読み込みは新しい共有リンクを作るため、元の共同編集プロジェクトを上書きしません。画像を含む読み込みファイルは 32 MB 以下です。**Follow the gradient** は、順伝播・損失・連鎖律を描く 13.3 秒の例です。25 個のオブジェクトと個々の動きをそのまま編集できます。

**Add image**、キャンバスへのドロップ、`Ctrl/Cmd+V` で PNG・JPEG・WebP を追加できます。一度に8枚まで。画像は縦横比を保ってサイズ変更でき、回転・不透明度・角丸・枠線・Glow、各 Composition の表示と Move・Write・Fade・Grow に対応します。Write は左から現れます。Shift を押しながら角をドラッグすると縦横比を変えられ、Inspector で元の比率へ戻せます。`@codex` で追加済み画像の配置や動きも依頼できます。

元画像は20 MB・4,000万画素まで。追加時に静止画像として長辺2,048 px・1 MB以下へ整え、透明部分を保持します。画像本体は部屋のサーバーに保存し、共同編集では参照だけを同期します。1部屋の画像容量は64 MBまでで、Undoや保存済みファイルの参照を保つため画像本体は削除しません。Cloudflare は同じ Durable Object の SQLite に128 KiBずつ分けて保存し、ローカル Node は `POIETRA_DATA_DIR`（初期値 `.data`）配下の `images/` を使います。プロジェクトの保存ファイルには画像を埋め込み、読み込み先の新しい部屋へ再保存します。画像を別プロジェクトにコピー＆ペーストする場合も、貼り付け先の部屋へ画像を保存してからオブジェクトを追加します。プレビュー・MP4・WebM にも画像を含みます。

Composition の ＋ は、最後の Composition の配置・内容・非表示状態を引き継ぎます。同じオブジェクトの各場面を独立して編集できます。テキスト・数式は追加すると内容欄に移り、既存のものはダブルクリックで再編集できます。文字の隙間もドラッグでき、Transition 下部の目盛り・再生ヘッドから時間を操作できます。

空白をドラッグすると範囲選択、Shift を押しながらドラッグ・クリックすると追加選択できます。Group／Ungroup で連結し、メンバーをドラッグすると表示中・未ロックのメンバーが一緒に動きます。Transition では複数対象の Move・Write・Fade・Grow・Cut、開始・長さ・Easing、Write の順序をまとめて設定し、各メンバーの移動パスを保持します。登場・退場する対象も設定できます。自動で付く Move もタイムラインに表示し、バーの最初の調整で編集可能なトラックとして保存します。選択するだけではデータを変更しません。

Composition のメニューから状態を複製・削除できます。同時に最後の状態を削除した場合も、全員が同じ1つの状態を保持します。取り消しで他の人の編集は戻りません。オブジェクトは `Ctrl/Cmd+C`・`Ctrl/Cmd+V` で別の Composition やプロジェクトへコピーでき、`Ctrl/Cmd+Shift+V` で元の位置に貼り付けます。切り取りは `Ctrl/Cmd+X`、`Delete` / `Backspace` は選択中の Composition から非表示にします。`Ctrl/Cmd+Z` で取り消し、`Ctrl/Cmd+Shift+Z` でやり直します。文字入力・日本語の変換中は入力操作を優先します。新しく追加したアニメーションについて、同期済みの共同編集者の変更を検知した場合は、その追加をUndoしてもトラック全体を保持し、画面に通知します。新規オブジェクトの名前・配置・アニメーションに共同編集者が手を加えた場合は、作成の Undo でもそのオブジェクトと各場面の状態・トラックを保持します。保持されるアニメーションが範囲外にならないよう、必要な Transition の長さも残します。相手が短くした Transition に長いアニメーションを Redo で復元しようとした場合は、変更せず理由を表示します。新しく追加した Composition を共同編集者が変更したり、そこから次の場面を追加した場合も、その追加バッチと依存するオブジェクト・動きを保持します。それ以外の自分の変更は通常どおり取り消します。未同期の編集は検知できないため、接続が切れている場合は合流後に取り消してください。矢印キーは1 px、Shiftと組み合わせると10 px移動します。数式の LaTeX 入力では `\` に続けて文字を打つと候補を表示し、↑↓ で選んで Tab か Enter で確定、Esc で閉じます。`\frac{}{}` のような雛形は最初の `{}` にカーソルを置きます。

上部の Scene メニューでは名前変更・複製・削除と **Move earlier / Move later** での並べ替えができます。Scene の順番が動画の再生順になります。複製した Scene のオブジェクトとアニメーションは独立して編集できます。Scene の同時削除でも1つを保持し、Undo は共同制作者の変更を残します。

上部の **Preview** は全 Scene を順番に再生します。場面のボタンやシークバーから移動し、**この場面を編集** でその Scene の Composition／Transition を開けます。Scene 内のタイムライン再生からは **この場面を編集** または `Esc` で再生位置の編集に戻ります。プレビュー中は、表示と異なる場面へのプロパティ編集・削除を防ぎます。上部の接続状態から、同期の進み具合とブラウザ内の保存状況を確認し、必要な場合に再接続できます。

Export は **Entire project / Current scene** の範囲選択と原寸・720p・1080pに対応し、開始時の全 Scene・順番・設定・ファイル名を保持します。複数 Scene がある場合はプロジェクト全体が初期選択です。全体の出力比率は先頭 Scene を使い、異なる縦横比の Scene は余白を入れて比率を保ちます。閉じる／Cancelで処理を中断し、完了後の **Download again** は同じ動画を再保存します。

**Chat** は同じ部屋のメンバー全員が会話できる共有チャットです。通常のメッセージは人間同士の相談になり、`@codex 円を黄色にして` のようにメンションすると AI が返答・編集案をチャットに出します。入力欄の **@codex** ボタンでも呼び出せます。AI の接続がなくても人間同士は会話でき、AI の処理中もメッセージを送れます。表示名は Share で変更できます。Scene のプレビュー中も会話でき、AI への依頼・適用は「この場面を編集」で表示中の場面へ戻ってから行います。

Codex は選択を依頼の文脈として使います。Composition を表示したまま関連する Transition の動きを頼んだり、同じ Scene 内の複数の Composition・Transition を明示して編集したりできます。提案カードに実際の編集対象を表示し、選択を戻さず Apply できます。移動パスや図形のベジェ制御点も変更でき、ロックや Apply 前の対象の変更は引き続き検証します。

新しいオブジェクトの作成と、別 Composition の配置・表示や Transition のアニメーションを一つの提案で設定できます。例えば「円を追加して次の場面までベジェで動かす」「数式を次の場面に追加して Write で登場させる」と依頼できます。Transition の長さも変更できますが、他のトラックを自動で縮めることはありません。Composition が1つだけの Scene でも「円を作り、次の場面へベジェで動かして」と依頼できます。AI は末尾に次の Composition と Transition を追加し、その場面の配置・登場・動きまで一つの提案にまとめます。一度に4場面まで、Scene全体では100場面まで追加できます。前の場面の配置はコピー時点で引き継ぎ、その後は独立して編集できます。追加予定の名前を確認して Apply すると、新しい Transition を開きます。AI による Scene の新設や既存 Composition 間への挿入は未対応です。

画像オブジェクト・Chat・AI による場面追加を使う前に、共有中のメンバー全員が画面を再読み込みしてください。

会話は部屋全体で共有・保存し、最新300件を表示します。Scene を切り替えても会話は残り、メッセージに依頼先の Scene・選択対象を添えます。再読み込み・オフラインからの再接続でも履歴と編集案を復元します。チャットは動画の Undo や保存用プロジェクト JSON に含めません。未読の発言は Chat タブに件数を表示します。

AI には現在の Scene の完了した直近24発言・合計24,000文字までを送り、他のメンバーの発言には表示名を添えます。AI を呼ぶのは `@codex` を送った画面だけで、受信した他の画面から同じ依頼を実行しません。編集案の内容・適用済み・破棄の状態も共有します。Apply と破棄は依頼した画面で行い、再読み込み後も同じタブから適用できます。以前の適用後に Undo や共同編集があっても、現在の Scene を実際の状態として使います。停止・失敗した依頼は次の会話文脈に含めず、再試行で同じ発言を重複させません。Scene を変えると自分の処理中の依頼を停止し、下書きは元の Scene に残します。

## デモの流れ

1. Share の URL を別の PC でも開き、円の位置や色を変更して同期を確認する。
2. Composition 2 を選び、同じ円の別の配置を調整する。
3. Transition を選び、Move と Equation の Write を別々に調整する。円を選び `Edit Bézier path` で移動経路を曲げる。
4. Preview で動きを確認する。Chat でメンバーと相談し、`@codex` で AI に変更を頼み、編集案を Apply する。
5. Export で MP4 または WebM を書き出す。Chrome / Edge を使用する。

検証では、別ブラウザ間の共同編集・オフライン編集の合流・取り消し、実 workerd の強制休止と再起動後の復元、キャンバス・タイムライン・ロック・レイヤー順・ファイル読み込みを確認します。AI は API を代替したテストで提案の競合、キャンセル、再試行を検証しています。共有環境の実 OpenAI API でも、選択した円の色やベジェ移動パスを変更する提案から Apply・別ブラウザへの同期・共同編集者の別プロパティ変更を保持した Undo まで確認済みです。

`images.spec.ts` は実画像の共有・保存と読み込み・ドロップと貼り付け・複数画像の Undo・AI の移動と Write・MP4/WebM の色と透明部分を確認します。`node tests/image-worker.integration.mjs` は別のローカル Workers を起動し、複数チャンクの画像をプロセス再起動後にも復元できることを検証します。

`project-playback.spec.ts` は実際の MP4 / WebM を書き出し、FFmpeg / ffprobe で Scene 境界・フレーム数・縦横比・書き出し中の共同編集からの独立性を確認します。このテストには FFmpeg が必要です。

`pnpm test:e2e` はローカルの専用ページで描画の待ち合わせ・中断・SVGへの復帰と書き出しダイアログの遅延応答も確認します。`POIETRA_TEST_URL` を指定した場合は、公開アプリで実行できる編集操作のテストを対象にします。

## 図形・数式と動画書き出し

`renderer.ts` は `Frame` を SVG に変換し、`painter.ts` は完成フレームを Canvas に描きます。`export.ts` の `exportScene` / `exportProject` は開始時点のデータをコピーし、各時刻の評価結果を同じ painter で描画してエンコードします。全体書き出しは一つのエンコーダーと時間軸を使い、Scene ごとの寸法・背景を保持したフレームを順番に渡します。数式・フォント・SVG 画像の読み込みは `rendering/`、コーデック判定と書き出しの中断処理は `exporting/` に分けています。

- 円、矩形、テキスト、数式、ベジェ曲線、矢印、数直線、画像。回転・不透明度・塗り・線・角丸・glow に対応。
- 数式は MathJax の SVG パス。Write は字形ごとの同時／順次描画。日本語と欧文テキストは同梱フォントの必要な部分を SVG に埋め込みます。
- MP4/H.264 と WebM/VP9（未対応時 VP8）を実際の WebCodecs API で判定。24/30/60 fps、指定サイズ、進捗、中断に対応。音声は含みません。

### 検証

Node.js 24、pnpm 10 と Chrome を使います。Rust が使えなくても同梱 WASM で確認できます。`pnpm` が PATH にない環境では以下の先頭を `corepack pnpm` に置き換えてください。

```bash
pnpm typecheck
pnpm test
pnpm exec vite build --config tests/e2e/export-build.config.ts
pnpm exec playwright test --config tests/e2e/export.config.ts
```

ブラウザテストは専用の Vite 検証ページを起動し、日本語を加えた初期デモを保存・デコードして、1280×720、30 fps、約3.4秒、102フレーム、表示内容、編集中のスナップショット、中断、非対応環境を確認します。動画・比較画像・JSON レポートは `test-results/export/` に保存します。本番ビルドを検証する場合は `EXPORT_PREVIEW=1` を環境変数に設定して同じブラウザテストを実行します。`CHROME_PATH` で実行する Chrome を指定できます。未指定時は Windows のインストール済み Chrome、他環境では Playwright の Chromium を使います。

### 制限

- `prepareScene(scene)` の完了後に `frameToSvg` と `objectBounds` を呼びます。数式は TeX の base / ams に対応し、未対応・不正な入力は安全なテキスト表示に戻ります。
- 通常テキストのサイズはブラウザでは読み込んだフォントで計測し、Node.js では近似値を返します。同梱フォントにない文字・絵文字は環境依存の表示です。
- MP4 の寸法は偶数。サイズ比率を変えると余白を入れて Scene の比率を保ちます。WebM は最終フレームを丸ごと保持するため、端数のある Scene は最大1フレーム未満長くなり、実際の長さを返します。
- エンコード・ファイル確定中の中断は、実行中の呼び出しが終わってから解放します。メモリ上で動画をまとめるため、まず短いハッカソン用動画を対象とします。

## 共通 Canvas 描画と WebGL2 Glow

`createFramePainter(canvas)`（[painter.ts](src/engine/painter.ts)）は、評価済みの `Frame` を Canvas に描きます。`prepareScene(scene)` を済ませ、同じ painter の `render(frame, { signal })` を直列に呼んでください。出力は Canvas の現在の寸法に合わせ、Scene の縦横比を保ちます。`dispose()` は描画中でも呼べ、繰り返し呼んでも安全です。契約は [painter-contract.ts](src/engine/painter-contract.ts) に従います。

- **描画**: 対象オブジェクトだけを透明な画像にし、GLSL の横・縦 Gaussian ぼかしと元画像の合成で Glow を描きます。強さと余白は SVG と同じ定義を参照します。Write・回転・不透明度・表示順を反映し、完成したフレームだけを出力 Canvas にコピーします。
- **数式の Write**: MathJax の字形パス・長さ・変形を一度準備し、Canvas の `Path2D` で描きます。完成した字形と描画途中の字形は同じパスを使い、進行度から輪郭と塗りを毎フレーム計算します。TeX が同じなら、色・文字サイズ・線幅・出力サイズの変更でも準備を再利用します。対応する形状は `g`・`path`・角丸のない `rect`。未対応の形状は数式単位で既存の SVG 画像に戻します。
- **図形の Write**: 円・角丸矩形・ベジェ曲線・矢印・数直線は、形状が変わるまで `Path2D` と長さを再利用します。SVG と Canvas が同じ寸法・矢印の先端・目盛・表示タイミングを参照します。Write の進行度や色の変更ではパスを作り直しません。寸法・制御点・角丸・先端の大きさが変われば、その形状を準備し直します。
- **文字の Write と色変更**: 行全体の配置を SVG で一度描き、塗りと線のマスクを1枚の画像にまとめて保持します。Together は行のクリップ、Sequential は全文の配置を保った各文字の不透明度で描きます。文字幅を一文字ずつ測り直さず、日本語・空白・結合文字の配置を保ちます。内容・文字サイズ・線幅・順序・出力倍率を変えるとマスクを更新し、色・位置・回転・不透明度・Glow の変更では再利用します。カラー字形を含む文字、Sequential の128文字超、4096 px四方に収まらないマスク、予算を超えるマスクはオブジェクト単位で SVG に戻します。
- **再利用と解放**: 位置・回転・不透明度だけの変化では完成画像を再利用します。`LayerCache` が painter ごとの画像・パス・文字マスクを所有し、同じ ID の更新時には必要な準備だけを引き継ぎます。削除・キャッシュからの退避・SVG 経路への切り替え・`dispose()` で不要な資源を解放します。保持画像、文字マスクとその作業用画像の RGBA 容量、形状ソースの UTF-16 容量の合計は 32 MiB まで。Path2D の内部メモリは計測できないため、数式1件を 2,048 字形・ソース 1 MiB、図形1件を最大13パスに制限します。全オブジェクトで共有する作業 Canvas 1枚と GPU のメモリは、この保持予算に含みません。Object URL は画像読み込み処理、GPU 資源は Glow renderer が所有します。準備中の文字マスクは完了してからキャッシュへ渡し、中断されたものは解放します。
- **継続動作**: 出力 Canvas は 2D、WebGL2 は内部 Canvas で使います。WebGL2 非対応・context lost・GPU の描画失敗・大きすぎる画像では、既存 SVG と Canvas 2D に切り替えます。`backend` は現在の経路を返します。画像読み込みの失敗は呼び出し側へ返し、中断は `AbortError` になります。
- **プレビューと動画**: 編集画面と MP4 / WebM の各フレームを同じ painter で描きます。プレビューは描画中の待機フレームを最新1枚にまとめ、描画済みの状態に選択判定を合わせます。動画は全フレームを描き、開始時点の Scene、出力サイズ、fps、進捗と中断の契約を維持します。

SVG と Canvas の輪郭のアンチエイリアスは完全一致しません。特に色付き文字は、SVG へ直接色を指定した場合と白いマスクを着色した場合で輪郭の濃さが変わります。日本語42 px・`#d66b9d`・Sequential 75% の比較では、RGB値の合計が約11.3%増え、完全不透明な内部1,069画素の色は一致しました。文字の配置や内部の欠落とは分けて検証しています。
